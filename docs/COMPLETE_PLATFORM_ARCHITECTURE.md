# Career Copilot V2 完整平台架构

## 1. 产品分层

Career Copilot 不再是写死少量岗位的个人页面，而是四层平台：

1. **平台岗位池**：收纳公开共享岗位和每个账号的私有岗位。
2. **岗位聚合层**：Greenhouse、Lever、Ashby 公开 ATS 自动发现；其他招聘平台通过真实 URL 与 JD 导入。
3. **用户画像与推荐层**：每个账号独立保存毕业年份、方向、地点、办公方式、行业、技能和时间条件。
4. **投递工作流**：用户选择岗位后，系统匹配简历、检查资格和材料；最终提交必须由用户明确确认。

## 2. 数据可见性

### 平台共享岗位

- `jobs.visibility = 'public'`
- 所有 authenticated 用户可读。
- 岗位基础事实由来源拥有者维护。
- 其他用户对届别、出勤、周期等的确认写入 `job_user_overrides`，不会修改其他人的判断。

### 个人私有岗位

- `jobs.visibility = 'private'`
- 只有创建该岗位的账号可见。
- 手动导入的岗位默认私有，避免把内推联系人或内部 JD 意外公开。

### 用户私有数据

以下数据均按 `user_id` 或所属 profile 隔离：

- 画像与偏好
- 项目证据
- 简历版本与岗位对齐
- 岗位评价
- 材料包
- 投递记录、事件和批次

## 3. 推荐与筛选

推荐采用三层逻辑，不能混为一个过滤器：

1. **完整池展示**：默认展示全部开放岗位。
2. **画像排序**：方向、技能、地点、办公方式、发布时间和已核验证据影响推荐分。
3. **硬性资格**：届别、在校资格、出勤、周期、截止日期决定能否进入投递准备。

画像不完整时仍展示全部岗位，但会提示完善画像，并把资格状态标记为待确认。

## 4. 投递链路

```text
完整岗位池
→ 用户点击“投这个”
→ 按账号画像检查资格
→ 对该用户的全部简历版本评分
→ 自动选择最匹配简历
→ 检查项目证据和额外材料
→ 有缺口：列出补齐任务
→ 无缺口：生成材料包
→ 用户明确确认
→ 打开真实招聘入口
→ 用户在招聘平台完成最终提交
→ 回到工作台标记已投递
```

系统不会保存招聘平台密码、Cookie 或验证码，也不会把“打开了页面”记录成“已经提交”。

## 5. 前端信息架构

核心工作区：

- 今日简报
- 岗位发现
- 岗位来源
- 投递管理
- 数据看板

个人资料：

- 我的画像
- 简历版本
- 项目证据

Carbon 风格只负责统一视觉层级，不能以“简化”为理由删除主干功能。

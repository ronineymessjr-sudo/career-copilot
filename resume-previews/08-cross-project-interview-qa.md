# 三个项目通用的面试答题框架

## 先讲清楚“参数”有三类

1. **已经在代码里生效的参数**：例如 Career Copilot 的 `0.4/0.4/0.2` 权重、PhotoAtelier 的 `retrieve_top_k=8`、Camera 的 `crawler_timeout_ms=45000`。可以直接说默认值和影响。
2. **由数据推导的量**：例如技能命中率、citation coverage、reply/interview/offer rate。它们不是一个可随便填的旋钮，应该通过回测和标注集调节。
3. **尚未开放的优化旋钮**：例如按渠道学习权重、外部 LLM seed、动态阈值。面试时说“下一步会这样做”，不要说成当前已经实现。

## 被问“调大/调小分别怎样”时的统一回答

- **召回参数**（top-k、overlap、低阈值）：调大/放宽，召回增加、噪声和成本也增加。
- **精度参数**（阈值、重排、硬 blocker）：调大/收紧，误匹配减少、漏检增加。
- **吞吐参数**（并发、重试、timeout）：调大通常提高成功吞吐，但会增加资源、限流和重复副作用。
- **信任参数**（证据类型、freshness、hash、approval）：不以“调大”为目标，而以“是否满足门槛”为目标；门槛不能用性能优化绕过。

## 被问“如何保证确定性”时的统一回答

我先把确定性边界拆开：哈希、规则、排序 tie-break、schema、状态机、队列领取和证据引用是确定性的；第三方 API、网页内容和外部 LLM 不是。对可控部分固定版本、输入、公式、内容 hash 和状态转换；对不可控部分记录 provider status、trace、时间和失败原因，必要时降级或要求人工复核，而不是伪造确定结果。

## 被问“无法使用怎么办”时的统一回答

1. 先返回可观察的状态：`available/degraded/failed`、trace/request id、错误类型和重试时间。
2. 选择不会越过安全边界的 fallback：Career Copilot 词法排序，PhotoAtelier 本地 deterministic planner，Camera 线索保留但禁止未验证信号。
3. 如果没有可信 fallback，就 fail closed：不写申请、不发邮件、不产生交易策略。
4. 恢复后通过队列或新版本重试，避免同一动作重复执行。

## 最后一条原则

面试时不要只背“用了 LangGraph、RAG、MCP、Cloudflare”。要说明：输入是什么、状态怎么走、参数改变会影响什么、失败时系统如何诚实地降级、哪一步必须由人批准。这样项目才从技术名词变成可运行、可解释、可维护的系统。
